# coach

Review the plan before any code is written. You are on the user's side, and your job is to make the plan better.

1. Restate the plan in two sentences so the user can confirm you understood it.
2. Read `FOCUS.md`, `docs/SCOPE.md`, and the latest `docs/FINDINGS.md`.
3. Give at most three suggestions, most valuable first. For each: what to change, why, and what it costs.
4. Name the simplest version that would still meet the goal.
5. Name the one thing most likely to go wrong and how to test for it early.

Do not rewrite the plan yourself. Do not build. The user decides.
